# Sensitive Data Guard（敏感数据门禁）

一次公开发布的泄露是不可逆的：PyPI 不允许删除版本，git 历史被克隆后就收不回来，
搜索引擎和镜像站会在几小时内缓存公开仓库内容。扫描多花两分钟，泄露的代价可能是
吊销凭证、通知客户、甚至法律后果。所以这里的规则是：**宁可误报，不可漏报**。

## 什么时候必须扫描（硬门禁）

在执行以下**任何一项**动作之前，必须先运行扫描并根据结果决定是否放行：

- `git push`（首次推送到远端，或新增公开远端）
- `twine upload` / 运行 `release.py`（不带 `--dry-run`）
- 创建/修改 PyPI Trusted Publisher、GitHub Actions 发布流水线
- 用户要求"发布/上传/公开/开源"这个项目

即使用户没有要求检查，也要主动扫描——大多数人意识不到 git 元数据和构建产物也会泄露。

## 怎么扫描

扫描器是确定性脚本（纯标准库），一条命令完成六个维度的检查：

```bash
python .claude/skills/sensitive-data-guard/scripts/scan.py --repo <仓库路径>
```

覆盖范围及原因：

| 维度 | 为什么 |
|------|--------|
| 工作区文本 | 代码/文档里硬编码的凭证、邮箱、手机号 |
| git 提交者元数据 | 作者姓名/邮箱随每次 push 公开（个人邮箱暴露可反查到人） |
| git 历史内容 | 现在删了 ≠ 历史里没有，checkout 旧提交就能拿到 |
| 历史中删除过的敏感文件 | `.env`、`*.pem` 等提交后删除的文件仍在历史中 |
| dist/ 产物解包 | wheel/sdist 才是 PyPI 真正分发的内容，egg-info 可能夹带已删代码 |
| 痕迹文件盘点 | `.idea/`、`.claude/` 本地文件、notebook 输出、二进制文件 |

可选参数：`--rules <toml>` 加载自定义规则、`--skip-history`、`--skip-dist`、`--json`。

## 结果处理（按退出码）

### 退出码 2 —— 存在高危：**硬阻止**

禁止执行发布/推送动作。直接告诉用户"发现高危问题，我不会执行发布"，列出问题清单，
并按 `references/remediation.md` 给出修复方案。典型高危：PEM 私钥、各平台 API token、
`.env`/`.pypirc` 出现在仓库、连接串内嵌密码、历史中删除过的敏感文件。

**唯一的例外**：用户明确说出「我已知晓风险，强制继续」（或同等明确的表述）时，
放行前再警告一次后果（不可逆、需吊销凭证），然后执行用户指定的动作——但只执行用户
明确要求的那一个动作，不要顺手做其他发布步骤。

### 退出码 1 —— 存在中危：逐条确认

列出每一项中危（个人邮箱、手机号、凭证样式的赋值、notebook 输出等），逐条问用户
"这条是测试数据/可以公开吗"。全部确认后才能继续。git 提交者个人邮箱默认按中危处理，
提醒用户可改用 GitHub noreply 邮箱。

### 退出码 0 —— 干净：放行，但带上两条提醒

1. 图片/二进制文件无法用正则检查，列出让用户人工确认截图里没有内网系统界面
2. 扫描只反映当下状态，以后每次发布前都会重新扫

## 修复（发现泄露后）

读 `references/remediation.md`，核心顺序是：

1. **先吊销/轮换凭证**——历史清理是第二步，凭证泄露后第一件事是让它失效
2. 再清理 git 历史（`git filter-repo`）并强推
3. PyPI 侧无法删除已发布版本，只能确保新版本干净 + 吊销泄露的 token

## 自定义规则（公司专属关键词）

内置规则覆盖通用模式。公司内部信息（内网域名、项目代号、工号段）需要自定义规则：

- 模板（可提交）：`.claude/sensitive-rules.example.toml`
- 实际规则（**绝不提交**）：`.claude/sensitive-rules.local.toml`（已在 .gitignore）

为什么实际规则必须 gitignore：如果规则文件里写着公司域名/内部系统地址，把这个文件
传上 GitHub 等于主动公布"这个仓库的作者属于哪家公司"——规则本身就是泄露。

用户让你加公司规则时：写入 local 文件，提醒不要提交；如果用户坚持要提交公司规则到
公共仓库，先警告一次再执行。

## 本 skill 自身的边界

- 本 skill 会随仓库公开，所以**不能**包含任何真实公司数据、真实邮箱、真实内网地址
- 报告输出中对高危命中做了打码（前 6 位 + 长度），避免扫描报告本身变成二次泄露源
  （报告可能进入会话记录、issue、聊天截图）
- 扫描器误报时，往 `.claude/sensitive-rules.local.toml` 的 `[allowlist]` 里加条目，
  不要改内置规则或删除扫描步骤
